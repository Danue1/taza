# 크로스플랫폼 키보드 아키텍처 청사진 v2
(v1에 대한 3방향 적대 검토 — 플랫폼 제약 / IME 도메인 / 엔진 조달·FFI — 반영판)

## 목표
- iOS(Keyboard Extension) + Android(InputMethodService) 키보드 앱
- 각 플랫폼이 지원하는 모든 언어 지원 (장기). 구현 순서: 영어 → 한국어 → 일본어,
  나머지는 추후 — 단 계약·팩 포맷은 추후 언어 특성(RTL, 무공백 스크립트 등)을 선반영
- sans-io 코어로 플랫폼 간 코어 동작 동일성 보장
- 언어별 composing 관습(UX) 최대한 재현
- 사전은 언어별 분리, 미리 다운로드한 언어만 사용, 영어는 앱에 내장(기본 언어)

## 전체 구조
```
Shell (플랫폼별)
  iOS: UIInputViewController / textDocumentProxy
  Android: InputMethodService / InputConnection
FFI: UniFFI (측정 게이트 아래 채택, 핫패스 C ABI 예비안)
Core (Rust, sans-io)
  fn handle(event: InputEvent, context: EditorContext) -> Vec<Effect>
```

### 크레이트 경계 (v2.5)
크레이트를 가르는 축은 **배포 단위** 하나다 — 익스텐션 바이너리에 들어가는가.
서브시스템·언어 경계는 크레이트가 아니라 모듈과 feature로 표현한다.

| 크레이트 | 자리 | 내용 |
|---|---|---|
| `taza-engine` | 온디바이스 | `contract`(`shell`·`event`·`candidate`은 FFI를 건너고 `composer`는 건너지 않는다) / `engine`(조립) / `keyboard` / `lang`(언어별 합성기) / `suggest`(후보·랭킹) / `policy`(언어 무관 관습) / `personalization` / `pack`(읽기 전용) |
| `taza-ffi` | 온디바이스 경계 | UniFFI 표면(`types`·`convert`·`session`), 팩 mmap 등 파일 IO |
| `taza-toolchain` | 오프라인 | `PackWriter`·`section`(섹션 빌더) + 단계(`recipe`·`source`·`parse`·`normalize`·`assemble`·`distribute`)와 그 순서를 쥔 `pipeline` + `taza-packs`·`taza-packc`(둘 다 인자 읽기와 출력만 맡는 실행 파일) |
| `taza-evaluation` | 오프라인 | 오타 합성·메트릭·CI 회귀 게이트 |

- 팩 포맷 상수·섹션 태그·와이어 레이아웃의 단일 출처는 `taza_engine::pack`이고,
  `taza-toolchain`은 그 위에 쓰기 경로만 얹는다. 읽기 코드가 익스텐션에 링크되고
  쓰기 코드는 링크되지 않는다.
- 언어는 feature로 켠다(`lang-latin`, `lang-hangul`). 셸은
  `--no-default-features --features lang-<언어>`로 미지원 언어 코드를 링크에서 제외하고,
  `Language::composer()`가 None이면 FFI 생성자가 `Unsupported`를 돌려준다.
- 언어 추가 = `taza-engine/src/lang/<언어>.rs` + feature + `Language` 등록. 외부 C++
  엔진 어댑터(일본어·중국어)는 이 규칙의 예외로 별도 `-sys` 크레이트를 optional
  dependency로 받는다.
- 모듈 안쪽도 같은 축으로 가른다 — **책임 하나에 파일 하나**. `keyboard`는 표현
  (`frame` — 상태를 읽기만 하는 순수 계산)과 판정(`hit`·`press` — 좌표가 상태를
  움직인다)을 갈라 두므로 확률 모델을 바꿔도 렌더 코드에 손이 가지 않고, 그 반대도
  같다. `engine`은 팩 교체(`pack`)·입력 진입점(`input`)·합성 뒤의 랭킹과 교정
  (`compose`)·통합 검색면(`annotation`)으로 나뉜다.

### 셸 원칙 (v2 재서술)
- 셸은 **입력 의미론**(composition·commit·삭제·후보 선택)에 분기를 갖지 않는다.
- 플랫폼 강제 분기는 화이트리스트로 명시하고 그 외 분기는 리뷰에서 거부:
  지구본 키 / inputType·UIKeyboardType별 레이아웃 요청(코어 입력으로 승격) /
  리턴키 라벨 / iPad 플로팅·분할 / 인라인 자동완성 제안(Android 11+) /
  Material You 동적 색상(테마 토큰 주입으로 코어 입력화) /
  IME_FLAG_NO_PERSONALIZED_LEARNING(EditorContext.incognito 플래그로 코어 전달)

### EditorContext (v2 — "앞뒤 N자" 계약 폐기)
- 문맥은 보장되지 않는다: `Option<ContextWindow>` + 신뢰도(fresh/stale/unavailable).
  iOS는 0~약300자·문단 절단·앱별 nil이 일상, Android InputConnection도 비동기·무응답 채널.
- 계약 기준은 "iOS"가 아니라 **양 플랫폼 실패 모드의 합집합**:
  문맥 비보장 + Effect 적용 비확인.
- Effect는 적용됐다고 가정하되, 다음 문맥 스냅샷과 불일치 시 재동기화하는
  reconciliation 규칙을 코어가 소유.
- 골든 코퍼스에 "문맥 0자" 케이스 필수 포함. 예측·교정 품질 설계도 문맥 0자에서 동작해야 함.

### composing 반영 전략 (v2 — "감지 후 fallback" 폐기)
- 호스트 앱의 marked text 지원 여부를 감지할 방법이 없다(양 플랫폼 공통).
- 따라서 fallback은 감지가 아니라 **언어별 정책**: 각 Composer가 iOS 안전 모드
  (예: 한국어는 marked text 대신 음절 단위 commit+delete)를 1급 출력 전략으로 제공.
  전략 선택은 코어 계약에 있고 셸 휴리스틱은 없다.

### 삭제 계약 (v2)
- `DeleteBackward`는 문자 수가 아니라 **코드포인트 수**(코어가 문맥 스냅샷에서
  그래핌·스크립트 규칙으로 산출)로 정의.
- iOS `deleteBackward()`는 count 미보장 API임을 셸 계약에 명시 — 삭제 후 문맥 재동기화 필수.
- 스크립트별 삭제 단위 정책 테이블(이모지 ZWJ=통째, 인도계 클러스터=코드포인트 등)을
  골든 코퍼스에 포함.

## 메모리·생명주기 (v2)
- 예산은 **최악 기기 하한 48MB** 기준(실측 산포 48~70MB, 상한 비공개·기기 의존).
- "힙 로드 금지·mmap 조회 전용"은 **코어 자체 사전에 한함**. C++ 엔진은 언어별 힙 예산
  상한을 두고, 로드 실패 시 해당 언어 비활성.
- 익스텐션 재생성은 키보드 표시마다의 일상 — 콜드 스타트 예산(키보드 표시까지 X ms)을
  명시하고, 지연 로딩 순서(레이아웃 먼저, 사전 나중)와 스냅샷 크기 상한을 설계에 포함.
- 사전 다운로드는 컨테이너 앱 전담, App Group 전달 (v1 유지 — 검토 통과).
  **구현됨**: 컨테이너 앱이 카탈로그(`TazaPackCatalogURL`)를 읽어 `.tazapack.zst`를 받고,
  코어(`install_pack_archive`)가 아카이브·팩 두 단계 sha256 검증 → 해제 → 임시 파일 →
  원자적 교체로 App Group에 놓는다. 원자적 교체라 익스텐션이 반쯤 쓰인 팩을 mmap하지 않는다.
  익스텐션은 `PackStore`로 설치된 팩을 우선하고 없으면 내장 팩을 연다 — 영어만 번들에 있고
  나머지 언어는 받아야 제안이 켜진다. 해제기는 순수 Rust(ruzstd)라 플랫폼별 분기가 없다.
  **잔여**: App Group 자체는 서명 팀이 붙은 뒤 활성화되므로 설치 경로의 기기 실증은 미완
  (검증·해제·교체 로직은 단위 테스트로 확인). 배포 호스팅도 아직 없다 —
  카탈로그 URL이 비면 앱이 "배포처 미설정"으로 표시한다.

## FFI 계약 (v2 — 이원화)
- **키 확정 이벤트**: 이벤트당 1회 왕복 (µs 오더, 문제 없음).
- **포인터 스트림**(다운/무브/업, 글라이드): 프레임 단위 배칭으로 왕복.
  시각적 프레스 하이라이트는 셸이 KeyboardFrame에 포함된 키 바운드로 즉시 처리
  (판정은 여전히 코어, 표시만 셸 선반영).
- KeyboardFrame은 전체 재전송이 아니라 diff/버전 넘버.
- 측정 게이트: 실기기 keydown→setMarkedText p99 실측 후 채택 확정,
  초과 시 핫패스만 수동 C ABI로 하강.

## 렌더링 (v1 결론 유지 — 검토 통과)
- **구현 현황**: KeyboardFrame(정규화 좌표 기하·접근성 라벨 포함), QWERTY·두벌식 내장
  레이아웃, 일회성 shift 상태 기계, 좌표→InputEvent 히트 테스트(v1 기하: 포함 → 같은 행
  최근접 스냅)가 taza-engine::keyboard에 구현됨. 확률(공간) 모델은 히트 테스트 지점 교체로
  들어온다. **배열은 코드다**(v3.3): 라틴 네 벌·한글 여섯 벌이 `keyboard::layouts`에 있고
  팩은 배열을 나르지 않는다.
- **폼팩터는 셸이 주입하고 치수는 코어가 정한다**: 셸은 플랫폼 값(size class 등)을
  `FormFactor`(폰 세로·폰 가로·태블릿)와 폭(pt)으로 번역해 `set_metrics`로 넘기고, 코어가
  행 높이·후보 바 높이·글자 크기를 정해 `KeyboardFrame.metrics`로 돌려준다 — 폼팩터 갈래가
  셸에 생기지 않는다. 행 높이는 배열이 정하므로(`LayoutRow::height`, 표준 행 대비 배수)
  줄이 하나 더 필요한 배열(세벌식의 네 줄)이 눌러 담아 높이를 맞춘다. 물리 거리로
  판정해야 하는 동작(커서 이동 감도)은 주입된 폭을 써서 화면 크기와 무관하게 일정하다.
- Flutter/Compose Multiplatform 기각(익스텐션 메모리·재생성 초기화 지연).
- 코어가 KeyboardFrame 소유, 셸은 네이티브 렌더러.
- **접근성은 비통일 영역이 아니라 계약의 일부** (v2): KeyboardFrame에 키별 롤·상태 포함.
  VoiceOver/TalkBack 터치 탐색은 OS가 히트 테스트를 대신하므로, 접근성 경로에서는 확률
  판정 없이 명시적 키 활성화 이벤트로 코어 진입.
- **문구는 화면 언어를 타므로 셸이 짓는다** (v2.9): 계약이 나르는 것은 **신원**이지 어느
  나라 말이 아니다. 코어는 역할(`KeyRole`)·갈래(`CandidateGroup`·`EmojiCategory`)·리턴키가
  시키는 동작(`KeyLegend`)만 밝히고, 접근성 문구·검색면 그룹 이름·리턴키 낱말은 셸이
  자기 문자열 카탈로그에서 꺼낸다. 글자·기호 키의 라벨은 그대로 코어가 준다 — 어느 나라
  말로 보든 같은 글자이기 때문이다.

## Composition 설계 (v2)

```rust
trait Composer {
    fn feed(&mut self, event: ComposerEvent, dictionary: Option<&Dictionary>) -> ComposerOutput;
    fn finalize(&mut self) -> Option<CommittedText>;
    fn snapshot(&self) -> ComposerState;
}
enum ComposerEvent {
    Key(KeyId), Backspace, CandidateSelected(usize), Separator(char),
    TimerFired(TimerId),                    // v2: 멀티탭 타임아웃. v3.2에서 다르게 앉았다 —
                                            // 주기 판정을 코어가 자리로 하므로 합성기는
                                            // 시각을 알 필요가 없다(Effect::SetTimer)
    CandidatePageRequested,                 // v2: 후보 페이지네이션
}
struct ComposerOutput {
    delete_before_commit: usize,            // v2: 확정 텍스트 치환 채널 (그래핌 단위)
    commit: Option<CommittedText>,
    composing: Option<ComposingText>,
    candidates: Vec<Candidate>,
    timer: Option<TimerRequest>,            // v2: Effect::SetTimer로 번역
}
struct CommittedText {                      // v2: String → 메타데이터 보존
    surface: String,
    reading: Option<String>,                // 재변환·학습·확정 취소용
    corrected_from: Option<String>,         // 자동교정 되돌리기용
}
struct Candidate { text, kind /* 예측|변환|교정 */, commit_policy /* 후행 공백 등 */ }
```

- Backspace는 Composer 내부 처리, composing 비어 있을 때만 셸 위임 (v1 유지).
- **확정 취소·재변환**: 코어가 최근 CommittedText 이력을 보관, commit 직후 Backspace는
  delete_before_commit로 확정분을 지우고 composing 복원.
- 후보 선택 후 연속 타이핑: 버퍼 전체 소비 시 리셋(새 시퀀스), 일부 소비 시 잔여 버퍼로
  재시작 (v1 유지 — 검토 통과).
- finalize의 언어별 정책을 명시: 병음=원문 로마자 확정, 일본어=1위 후보 또는 가나 확정,
  한국어=현재 음절 확정. 골든 코퍼스에 finalize 케이스 포함.

### Composer 골격 (v2 — 3개 → 4개)
| 골격 | 특성 | 언어 |
|---|---|---|
| Direct | composing 없음, 팝업/데드키 (CLDR 데이터) | 라틴 전반 |
| Validated | Direct + 문맥 1자 수용/거부 + composing 없는 사전 제안·치환 | 태국어(WTT 2.0), 크메르어(coeng 정규화), 버마어 |
| Automaton | 결정적 상태 기계 + 타이머 | 한국어(두벌식·천지인), 베트남어(텔렉스), 인도계 네이티브 |
| Convert | 원시 버퍼 + 사전 변환 + 후보 바 | 일본어, 중국어, 인도계 음역 |

- 한국어 도깨비불 (v2 수정): "즉시 확정" 폐기. **composing 창을 직전 1음절 + 현재 음절로
  유지**해 도깨비불 전이 시에도 marked text 안에서 처리 — Backspace로 "가바"→"갑" 복귀가
  Composer 내부에서 자연스럽게 성립. 확정은 창이 밀려날 때.
- 베트남어: old style(òa)/new style(oà) 성조 표기 양쪽 지원 + 외래어 이스케이프(더블 타이핑
  복원)를 요구사항에 포함 — 후자는 영어 사전 조회 필요(순수 오토마타 아님).
- Validated 골격의 순서 검증은 문맥 1자 필요 — 문맥 unavailable 시 검증 생략을 정책으로 명시.

## 엔진·컴포넌트 조달 (v2)
| 컴포넌트 | 방침 |
|---|---|
| 한국어·베트남어·인도계 네이티브 조합 | 직접 구현 (조합 오토마톤은 소규모 — 단 교정·예측은 별도 계상) |
| 라틴 Direct + CLDR 데이터 | 직접 구현 |
| **라틴(+한국어) 자동교정·예측 엔진** | **직접 구현, 최대 단일 컴포넌트로 승격 계상**: n-gram LM + 편집거리/FST + 공간(터치) 모델. v1은 키 기하 기반 Gaussian 프라이어 + 온디바이스 적응(스냅샷에 포함), 로그 부재로 인한 초기 품질 한계를 리스크에 기록. **1차 구현됨(LatinComposer)**: lexicon 완성 + OSA 거리 1 교정 + separator 자동교정 + 제안 치환 — LM·공간 모델·개인화는 미착수 |
| 중국어 | librime(BSD-3) 채택 검토 — 조건부 (아래) |

## 데이터 자산 전략 (v2.1 — 사전·언어모델·랭킹)

### 원칙: 데이터 파이프라인을 1급 서브시스템으로
- 산출물이 아니라 **컴파일러를 소유한다**: `원천 코퍼스/어휘 → 정제 → 언어팩 바이너리`를
  재현 가능한 오프라인 파이프라인(dictionary compiler)으로 구축. 언어 추가 = 이 파이프라인에
  데이터 소스를 꽂는 작업이 되도록.
- 원천별 라이선스·출처·버전을 팩 메타데이터에 기록 (라이선스 지뢰 대비 감사 추적).

- **구현됨 (taza-toolchain, `taza-packs`)**: 레시피 하나로 조달부터 배포 산출물까지 돈다 —
  `data/recipes/<언어>.toml`(크기 예산·승격 문턱) + `<언어>.sources.d/*.toml`(원천 선언) →
  `source`(조달·해시 검증·추출 결과 캐시·압축 해제) → `parse`(형식별 파서) →
  `normalize`(병합·승격·점수 정규화) → `assemble`(팩 조립) →
  zstd 아카이브 + `catalog.json` + `NOTICE.md` 자동 생성.
- **원천이 다른 축 넷은 따로 움직인다**: 어디서 구하는가(`source::acquire` — URL 또는 손으로
  갖다 놓는 `file`), 어떻게 압축돼 있는가(`source::container` — tar.gz·zip·gz·bz2·평문),
  어떤 형식인가(`parse/*.rs` — 형식 하나가 파일 하나), 팩에 무엇으로 기여하는가
  (`recipe::Role`). 새 원천은 이 넷의 조합이므로 대개 조각 TOML 한 장으로 들어오고,
  정말 새로운 형식일 때만 `parse`에 파일이 하나 는다.
- **신호는 종류로 나뉜다**: 사전이 보증한 것(`attested`, 흔함 등급)과 코퍼스가 관측한 것
  (`observed`, 횟수)을 따로 담는다. 한 필드에 겸하게 하면 원천이 둘 중 하나만 될 수 있는데,
  전문용어 목록처럼 *표제어를 보증하면서 동시에 어절 빈도와 결합을 아는* 원천을 그러면
  표현할 수 없다. 구(句) 용어는 어절로 쪼개 표제어로, 이웃 짝은 문맥으로 들어간다.
- **원천을 다시 훑지 않는다**: 파이프라인 시간의 거의 전부가 파싱이다(위키백과 덤프 하나가
  6분 30초). (원천 해시 ‖ 추출 선언 ‖ 언어 ‖ `PARSER_VERSION`)을 키로 추출 결과를 캐시해
  두 언어 전체 빌드가 10초에 끝난다. 파서를 고치면 `PARSER_VERSION`을 올려야 한다 —
  안 올리면 낡은 캐시가 조용히 쓰인다(`--no-cache`가 탈출구).
- **언어 지식은 `lang`에 모은다**: 조사·파생 접미사·활용 축약·대소문자 규칙이 추출기와
  정규화에 흩어져 있으면 접사 하나를 손보는 일이 코드 세 군데를 고치는 일이 된다.
- 원천이 조용히 바뀌면 sha256 검증에서 빌드가 멈춘다 — 재현성의 최소 조건.
- **말뭉치는 계속 늘어난다**, 그러니 원천 목록은 레시피 본문이 아니라 조각 디렉터리
  (`source_directory`)에 둔다 — 새 말뭉치를 들이는 일이 조각 TOML 하나를 떨구는 일이 된다.
  이용 신청·로그인을 거쳐야 하는 원천(모두의 말뭉치, 우리말샘)은 URL 대신 `file` 경로로
  선언하고, 자리에 없으면 그 원천만 건너뛴다. 받은 만큼만 반영되고 빌드는 늘 돈다.
- **사전은 외래어·신어에서 늘 뒤늦다**. `role = "discovery"` 원천은 빈도를 보태는 데
  그치지 않고, `[lexicon.admission]` 문턱(최소 관측 횟수·최소 원천 수·상한)을 넘은 낱말을
  인벤토리 없이 표제어로 올린다. 승격 판정은 가중치를 먹이지 않은 관측 횟수로 하므로
  weight를 낮게 준 원천도 새 낱말을 대는 몫은 그대로 한다. 무엇이 들어왔는지는
  `data/build/<이름>-promoted.tsv`가 남긴다 — 문턱을 조일지 풀지는 이 목록을 보고 정한다.
- **이모지는 사전 곁에 붙는다 (emoji 섹션, 태그 5)**: CLDR 주석에서 (낱말 → 이모지)를
  뽑아 lexicon과 **같은 조회 키 공간**에 담는다. 그래야 치고 있는 어절을 그대로 들고
  물어볼 수 있다. 어절 하나로 치는 낱말만 받고("활짝 웃는 얼굴" 같은 대표 이름은 후보 바의
  단위가 아니다), 사전에 있는 낱말에만 단다. 후보 바에서는 낱말 뒤에 곁들여지며 어절이
  완성된 뒤에만 나온다 — 이모지가 낱말이 설 자리를 가져가서는 안 된다.
  한국어 2,798낱말 59KB, 영어 3,103낱말 66KB.
- **고지 문서를 손으로 쓰지 않는다**: 레시피의 저작자 표시가 NOTICE·팩 메타데이터·설정
  화면("사전 출처")으로 함께 흐른다. 자리에 없어 건너뛴 원천은 고지에 오르지 않는다.
  팩 메타데이터는 **원천 하나가 한 줄**이고 그 줄이 이름·판·라이선스·표시 문구를 모두
  갖는다 — 이름과 문구를 따로 두면 짝이 위치로만 맞아, 문구가 빈 원천 하나에 전부
  어긋난다. 설정 화면은 원천마다 한 행으로 그리고 문구 속 주소를 링크로 만든다.
- **라이브러리 고지도 손으로 쓰지 않는다**(`taza-licenses`): `taza-ffi`의 정상 의존성
  closure를 훑어 `data/licenses.json`(앱 자원)과 `SOFTWARE-NOTICE.md`를 낸다. 세는 기준은
  **기기에 나가는 것**이다 — 절차적 매크로는 크레이트 자신만 오르고 그 의존성은 따라가지
  않으며, 켜지지 않은 선택적 의존성은 뺀다(`cargo metadata`의 resolve 그래프는 그것까지
  간선으로 싣는다). 바인딩 생성기를 `cli` 기능 뒤로 옮겨 배포물이 clap·askama를 끌고 가지
  않게 한 것도 이 목록을 정확히 만들기 위해서다.
- 점수는 절대 빈도가 아니라 [1, 65535] 로그 스케일 정규화값이다. 절대 빈도를 실으면
  (1) 흔한 낱말이 개인화 가중치를 압도해 학습이 랭킹에 닿지 못하고, (2) 원천을 갈면
  스케일이 달라져 평가 비교가 깨진다.

### 언어팩 바이너리 포맷 (공용, mmap 조회 전용) — 컨테이너·lexicon 섹션 구현됨 (taza-engine::pack, taza-toolchain)
- 헤더(포맷 버전·언어·서명) + 섹션 테이블. 섹션 타입은 확장 예약:
  lexicon(FST/DAWG) / n-gram LM(양자화 trie) / **emoji(CLDR 주석) — 구현됨** /
  오타 confusion 데이터 / 언어별 부가 섹션(가나-한자 매핑, 병음 테이블 등).
  태그 3은 배열이 팩에 실리던 시절의 자리이고 다시 쓰지 않는다(v3.3).
- 스크립트 특성 메타데이터 포함: 어절 분리 유무, 클러스터 규칙, RTL 여부,
  composing 골격 종류 — 언어가 자기를 데이터로 선언하되, 그 골격과 배열은 코드에 있다.
  **구현됨(포맷 v3, metadata 섹션 태그 4)**: 판 번호·레시피·표제어 수·저장 인코딩·어절
  분리·RTL·원천 목록·저작자 표시. 조회는 키 이진 탐색, 미지 키는 그냥 무시된다.
- 개인화 데이터는 팩과 분리된 별도 스토어(사용자 unigram·최근성) — 팩은 항상 읽기 전용.
- **lexicon 크기 가공(포맷 v3)**: 접미사가 같은 하위 그래프를 합치고(DAWG 최소화, 컴파일러
  단계) 빈도를 u16 정규화 점수로 담아 노드 헤더를 4바이트로 줄였다. 리더는 노드를 offset으로만
  다루므로 조회 경로는 그대로다. 실측 — 영어 80k 표제어 1586KB(미최소화 추정) → **780KB**,
  한국어 120k 3903KB → **828KB**.
- **전송 압축은 팩 밖에서**: 기기에서 mmap 조회로 읽으므로 팩 자체는 압축하지 않고,
  배포용 `.tazapack.zst`(영어 344KB, 한국어 319KB — 원본의 약 40%)만 압축한다. 해제·검증·
  설치는 `taza-ffi`의 설치 경로가 맡는다.

| 일본어 | AzooKeyKanaKanjiConverter 사전(Apache-2.0)을 기반, 부족분 보강 | 랭킹은 엔진 내장 + 아래 개인화 레이어를 코어 측에 |

### 랭킹: 오프라인 평가 하네스가 튜닝의 전제 — 구현됨 (taza-evaluation)
- 레이아웃 기하 기반 오타 합성(인접 치환·전치·탈락·삽입, 시드 고정 결정론) +
  top-1/top-3·MRR·자동교정 정확도·keystroke savings + 임계값 CI 게이트(tests/gate.rs).
  합성 사전 영어 기준선(seed 42): top1 0.90 / top3 0.98 / MRR 0.94 / autocorrect 0.92 / KS 0.62.
- **실팩 보고 도구 구현됨**(`taza-evaluation --example pack_report`): 팩 교체 A/B 판단 자료.
  점수표 상위 500 낱말 기준(seed 42) — 영어 top1 0.723 / top3 0.864 / MRR 0.788 / KS 0.393,
  한국어 top1 0.956 / top3 0.996 / MRR 0.975 / KS 0.469. 라이선스 안전 원천으로 갈아탄 뒤
  종전 OpenSubtitles 파생 데이터(영어 top1 0.658, 한국어 0.940)보다 나아졌다. 단 한국어는
  표제어 구성이 어절→형태소로 바뀌었으므로 이 수치는 커버리지 비교가 아니다 — 종전 어절
  상위 2000 중 50%만 수록된다(조사 결합 생성 전 34%).
- 평가 셋: 언어별 (입력 시퀀스 → 의도 텍스트) 쌍 코퍼스. 실사용 로그가 없는 초기에는
  공개 오타 코퍼스 + 코퍼스에서 합성한 오타(터치 기하 기반 노이즈 주입)로 구성.
- 메트릭: top-1/top-3 정확도, MRR, keystroke savings. CI 회귀 게이트로 등록 —
  랭킹 가중치 변경은 이 게이트를 통과해야 병합.
- 랭킹 함수 구조: `score = LM 확률 + 터치 공간 모델 + 편집거리 + 개인화 부스트`의
  가중 결합으로 시작(가중치는 평가 하네스로 튜닝), 학습형 랭커는 데이터 축적 후.
- 온디바이스 개인화: 사용자 unigram 빈도 + 최근성 부스트. 코어 스냅샷에 포함,
  incognito 플래그 시 학습 중단. 원격 로그 수집은 하지 않음 — 개선 신호가 필요해지면
  온디바이스 집계 요약 + 명시 동의 방식으로 별도 설계.
  **구현됨(PersonalizationStore + ComposerEnvironment)**: 논리 시계 기반 최근성,
  용량 상한 축출, 학습 단어 자동교정 억제, 미등재 원문 후보(as-typed)를 통한 학습 경로,
  개인화 접두 완성, 스냅샷 직렬화. EditorContext.incognito가 학습 게이트.

## 빌트인 UX 계승 원칙 (v2.3 — 제품 방향)
플랫폼 순정 키보드의 익숙한 동작을 기준선으로 삼는다. 의도적으로 다르게 갈 때만 근거를
문서화한다.

구현됨: 한국어 iOS는 순정 관행대로 **밑줄 없는 commit+delete 전략**(셸이 SetComposing을
diff 삭제+삽입으로 번역, marked text 미사용 — 비협조 앱 호환 문제도 함께 해소),
더블 스페이스 → ". "(코어, 영·한 공통), 키 프레스 하이라이트(셸),
ClearComposing 셸 계약(unmarkText/finishComposingText는 "확정"이므로 빈 문자열 치환 후
종료), textDidChange 기반 composing 불일치 감지 → finalize(재동기화 셸 구현).

추가 구현됨(v2.4): **심볼 레이어** — KeyboardLayoutSet(레이어 0=문자, 1=심볼1, 2=심볼2,
iOS 순정 배열) + KeyAction::LayerSwitch, 레이어 전환 라벨 관례(ABC/한글·123·#+=).
**inputmode 대응** —
EditorContext.field(FieldKind: Text/Email/Url/Number/Phone/Password), Text 외 필드에서
제안·자동교정·개인화 학습 차단, iOS 셸이 keyboardType·isSecureTextEntry 매핑.

추가 구현됨(v2.5): **다국어는 키보드가 자체 관리한다** — 지구본은 시스템 키보드끼리의
전환이므로, 우리가 지원하는 언어의 목록·순서·최근 언어는 셸(설정 앱)이 소유한다.
- 하단 행 순서를 **심볼 · 언어 · 스페이스 · 엔터**로 고정, 언어 키를 `KeyAction::LanguageSwitch`로
  코어에 승격(탭 = `ShellRequest::NextLanguage`, 목록은 셸 소관). 스페이스바는 순정처럼
  현재 언어명을 표기.
- `FrameKey.role`(KeyRole)과 `alternates`를 프레임에 실어 셸이 **키 역할로만** 길게 누르기를
  분기하게 했다: 글자 = 변형 문자 팝업(스와이프 선택), 스페이스 = 커서 이동, 언어 = 설정·언어 목록.
- **글자 변형**은 배열이 싣는다(`LayoutKey::alternates`) — 라틴 네 벌이 표 하나를 나눠
  쓰므로 한 배열에서만 변형이 빠지는 드리프트가 없다. 한글 자모는 순정대로 변형 없음.
- **커서 이동**: `InputEvent::CursorDrag` → `Effect::MoveCursor`(논리적 이동, 코드포인트).
  셸은 포인터 x만 흘려보내고 몇 칸 옮길지는 코어가 판정(`Keyboard::*_cursor_drag`).
  이동 전 composing은 언어별 규칙으로 finalize.
- **디자인 시스템**(platforms/ios/TazaDesignSystem): 라이트·다크 동적 색과 그리는 방식
  (가로 간격 6pt·모서리 5pt·키 높이 대비 세로 간격 비율)을 토큰으로 두고 키보드와 설정 앱이
  함께 쓴다. 높이·글자 크기 같은 실측 치수는 코어가 프레임에 실어 주므로 토큰에 두지 않는다. 키를 개별 뷰(KeyCapView)로 그려 **접근성**을 계약대로 노출한다 —
  키별 라벨·`.keyboardKey` 트레잇·언어 키 value·변형 문자는 VoiceOver 커스텀 액션, 활성화는
  확률 판정 없이 키 중심 좌표로 코어 진입.
- **최근 언어 유지**: 언어 설정은 `LanguagePreferences`(App Group 우선, 없으면 표준 저장소)에
  보관해 다른 키보드를 거쳐 돌아와도 마지막 언어로 뜬다. App Group 공유는 서명 팀이 붙은
  뒤 활성화 — 현재 개발 빌드는 익스텐션 자체 저장소로 동작.
- 익스텐션 → 설정 앱은 `taza://settings` 딥 링크(응답자 사슬로 open).
- **사전 상태는 언어 목록 안에**(순정 키보드 관례): 행 오른쪽에 내장·다운로드·갱신·삭제가
  붙고, 상태는 별도 장부가 아니라 설치된 팩의 메타데이터에서 읽는다(단일 출처). 원천
  저작자 표시도 같은 메타데이터에서 읽어 "사전 출처" 절에 싣는다 — 라이선스 고지가 데이터와
  함께 움직인다.

추가 구현됨(v2.6): **입력 보조 설정은 우리가 소유한다** — 순정 키보드의 설정은 양
플랫폼 모두 서드파티가 읽을 수 없다(iOS는 설정 → 일반 → 키보드의 토글을 익스텐션에
열어 주지 않고, Android는 IME마다 자기 설정 화면을 갖는다). 값의 주인은 우리 설정
앱이고, 셸은 저장소에서 읽어 코어에 주입만 한다.
- `UserPreferences`(자동 수정 / 예측 / "." 단축키 / 입력 학습)를 팩과 별개로 세션에
  주입(`set_preferences`) — 팩 교체와 무관하고, 설정 화면에서 바뀐 값은 다음 키보드
  표시 때 반영된다(익스텐션 재생성을 기다리지 않는다).
- **판단은 코어가 결합한다**: `policy::assistance`가 사용자 설정 ∧ 필드 성격(`FieldKind`)을
  묶어 `Assistance`(correcting·predicting·personalizing)를 내고, 학습 기록만 추가로
  incognito를 본다. 셸에는 새 분기가 생기지 않는다.
- **입력 학습을 끄면 조회도 멈춘다**: `SuggestionSources.personalization`이 `Option`이라
  꺼진 입력에서는 개인화 스토어를 아예 참조하지 않는다. 껐는데 예전에 배운 말이 계속
  순위를 흔들면 설정이 한 일이 사용자 눈에 보이지 않는다. 지난 것을 지우는 쪽은
  `reset_personalization`(순정의 "키보드 사전 재설정")이 맡아 설정과 짝을 이룬다.
- 언어와 무관한 규칙(더블 스페이스 마침표)은 합성기가 아니라 Engine이 합성기보다 먼저
  본다 — 규칙 하나를 끄는 설정이 언어 수만큼 늘어나지 않게.
- iOS 설정 앱은 App Group `TypingPreferences`에 쓰고, 익스텐션은 `viewWillAppear`에서
  모든 언어 세션에 주입한다. 학습 스냅샷도 같은 리듬이다 — `LearningStore`에서 복원하고
  (스냅샷이 비었으면 코어 학습도 비운다) 키보드가 내려갈 때 저장한다.
- **값은 저장소로, 신호는 알림으로**(`SettingsBroadcast`): App Group `UserDefaults`의 변경
  통지는 프로세스를 넘지 않으므로, 앱이 값을 쓴 뒤 Darwin 알림을 던지고 익스텐션이 그것을
  받아 저장소를 다시 읽는다. 알림에는 내용이 실리지 않는다 — 받는 쪽은 늘 저장소가 정본이다.
  갈래는 둘이다: 설정 일반과 학습 스냅샷. **학습 스냅샷에는 쓰는 쪽이 둘**이라(익스텐션은
  치며 배우고 앱은 지운다) 설정 하나를 바꿀 때마다 스냅샷을 되씌우면 저장되지 않은 학습이
  되감긴다. 그래서 스냅샷은 앱이 실제로 손댔을 때만 다시 읽는다.
- **App Group 미활성 상태의 한계**: 서명 팀이 붙기 전에는 앱과 익스텐션이 각자의 저장소로
  물러나므로 **설정 앱에서 바꾼 타이핑 설정·학습 재설정이 키보드에 닿지 않는다**. 언어
  설정은 키보드에서도 바꿀 수 있어 우회되지만 이쪽은 우회로가 없다 — 기기 실증은 App
  Group 활성화 이후로 미뤄져 있다.

추가 구현됨(v2.7): **필드가 화면을 정한다** — 필드 성격은 보조 기능만이 아니라 배열·
리턴키·후보 바 자리를 함께 정한다. 판단 기준은 순정 실측표(`docs/inputmode.md`)이고,
셸은 플랫폼 값을 `FieldKind`로 옮기고 화면이 바뀔 때 다시 알려 주기만 한다.
- `FieldKind`에 `Search`·`Decimal`을 더했다. 검색 필드는 순정처럼 **예측을 그대로 두고**
  리턴키만 바뀌므로 `assistance_enabled`가 Text 하나가 아니게 됐다.
- `keyboard::field`가 필드 → 배열 변환을 한 곳에서 한다: 숫자 계열은 3열 숫자 패드(좌하단만
  필드마다 다르다), 이메일은 스페이스 양옆에 `@`·`.`, URL은 스페이스를 `.`·`/`·`.com`으로,
  비밀번호는 이모지 키와 언어 키를 걷어낸다. **프레임과 히트 테스트가 같은 변환 결과를
  본다** — 눌린 자리와 그려진 자리가 어긋나지 않게 하는 조건이다.
- 후보 바 자리도 코어가 정한다: 예측을 내지 않는 필드에서는 `candidate_bar_height`가 0이라
  키보드가 낮아진다(순정 실측). 비밀번호 필드는 순정이 그 자리를 암호 관리자에 내주므로
  자리를 남긴다.
- **다중 문자 키**(`KeyAction::Text`)와 **빈 자리**(`KeyAction::Blank`)를 더했다.
  `.com`은 어절을 끊으므로 조합을 먼저 확정하고 넣는다.
- `FrameKey.emphasized`로 강조 키(검색 필드의 리턴키)를 코어가 지목하고, 어떤 색인지는
  셸의 디자인 시스템이 정한다. 셸에는 새 분기가 아니라 새 겉모습만 생겼다.

추가 구현됨(v3.0): **앱이 밝힌 것은 사용자 설정보다 세다** — `FieldTraits`(리턴키·자동
대문자화 범위·자동 수정 허용·짝맞춤 부호 허용)를 필드가 바뀔 때 주입하고,
`policy::assistance`가 사용자 설정과 AND로 묶는다. 코드 입력란처럼 앱이 자동 수정을
끄라고 한 자리에서 우리 설정이 이기지 않는다. 리턴키는 아홉 갈래(`ReturnKey`)를 모두
받아 `KeyLegend`로 나가고, 이메일·URL·비밀번호에서는 셸이 라틴 배열로 연다
(`Engine::field_prefers_latin`).

추가 구현됨(v3.0): **글자 크기 설정을 따른다** — `KeyboardMetrics.text_scale`을 셸이
플랫폼 값에서 옮겨 주고 코어가 글꼴에만 곱한다(키 높이에는 곱하지 않는다 — 순정도
라벨만 커진다). 상한을 두어 라벨이 키를 넘지 않게 한다.

추가 구현됨(v3.0): **텍스트 대치**(`Engine::set_shortcuts`) — 사람이 손수 적은 대치는
사전이 미루어 짐작한 자동교정보다 세다. 확정 직후 Backspace로 친 대로 되돌아오는 길은
자동교정 되돌리기와 같은 통로를 쓴다.

추가 구현됨(v3.1): **세벌식은 새 합성기가 아니라 배열 데이터다** — 자리(초성·중성·종성)를
자모가 스스로 밝히면 합성기가 앞뒤를 추론할 일이 없어진다. 배열이 호환 자모(ㄱ, U+3131)를
내면 그 자모가 초성인지 종성인지는 추론해야 하고(두벌식), 조합용 자모(초성 U+1100·중성
U+1161·종성 U+11A8)를 내면 자리가 코드포인트에 이미 실려 있다(세벌식).
- `HangulComposer`에는 모드가 없다. `jamo::place`가 자모마다 자리를 가르고, 자리를 밝힌
  초성은 언제나 새 음절을 열며 자리를 밝힌 중성은 앞 음절의 종성을 넘겨다보지 않는다 —
  **도깨비불이 세벌식에서 저절로 일어나지 않는다.** 겹받침·복합 모음을 한 키로 내는 자리가
  있으므로 자모 하나가 곧 한 타건이고, Backspace도 그 단위로 되돌린다.
- **조회 키는 배열과 무관하다**: 사전은 두벌식 타건 순서로 저장되므로, 어느 배열로 쳤든
  `encode_jamo_ascii`가 자모를 두벌식 타건 단위로 쪼개 같은 키를 만든다. 배열을 늘리는 일이
  사전을 다시 짓는 일이 되지 않게 하는 조건이다.
- **키캡은 호환 자모로 그린다**: 조합용 자모는 홀로 놓이면 글꼴이 점선 동그라미를 달거나
  좁게 그린다. 사람에게 보일 때만 옮기고(`lang::keycap_form`) 합성기가 받는 값은 자리를
  그대로 지닌다.
- 배치는 세벌식 최종(3-91)을 그대로 옮겼다(libhangul `hangul-keyboard-3f` 기준). 데스크톱에서
  치던 손이 통하도록 숫자열 자리까지 네 줄을 싣고, 행 높이를 0.75로 눌러 담아 다른 배열·다른
  면과 키보드 전체 높이를 맞춘다. 시프트가 기호를 내던 자리는 기호가 이미 심볼면에 있으므로
  비웠다.
- **잔여**: 실기기 타건 검증은 미완.

추가 구현됨(v3.2): **배열이 자기 골격을 밝힌다** — 세벌식은 자모에 자리를 실어 배열
데이터만으로 끝났지만 천지인은 조합 규칙 자체가 다르다: 두벌식에서 ㅏ 뒤의 ㅣ는 새
글자인데 천지인에서는 ㅐ다. 한 표로 둘을 겸하면 둘 중 하나가 틀리므로, 골격을 언어만이
아니라 **배열도** 밝힐 수 있게 했다(`NamedLayoutSet::skeleton`). 청사진이 예약해 둔
"한 언어에 복수 Composer 등록"이 이 통로다.
- **천지인 합성기는 타건을 모음으로 옮기는 일만 한다**: 음절을 쌓는 규칙은 두벌식과
  같으므로 `HangulComposer`를 속에 두고, 하늘(ㆍ)·땅(ㅡ)·사람(ㅣ) 타건을 표 하나로 모음에
  대응시킨다. 표의 키는 **쌓인 타건 전체**라 늘어나는 도중의 모음이 다음 모음을 가리지
  않는다(ㅡㆍㆍ는 ㅠ이고 ㅡㆍㆍㅣ는 ㅝ다). 모음이 늘어날 때는 지우고 다시 넣는 두 걸음을
  속 합성기에 그대로 넘기므로 조합 창·어절 추적이 따로 볼 것이 없다.
- **하늘 하나는 아직 글자가 아니다**: ㆍ만 친 상태는 조합 창에 넣지 않는다. 그 자리에서
  확정해도 아래아가 문서에 남지 않는다 — 순정 천지인이 잠시 ㆍ를 보여 주는 것과 다르지만,
  글자가 아닌 것을 문서에 넣지 않는 쪽을 골랐다.
- **멀티탭은 배열 + 시간이다**(`KeyAction::Multitap`):
  주기의 내용은 배열이 정하고, 지금 몇 번째인지는 코어가 **자리**로 판정한다(다른 키를
  누르면 그 자리에서 주기가 끝난다). 시간만 셸이 잰다 — 코어가 `Effect::SetTimer(밀리초)`로
  시한을 요청하고 셸은 앞선 타이머를 갈아 끼운 뒤 `timer_fired`를 부른다. **끄는 명령은
  두지 않았다**: 이미 끝난 주기에 울린 타이머는 코어에서 아무 일도 하지 않으므로 셸이
  "지금 꺼도 되는가"를 판단할 일이 없다. 이어 누름은 `InputEvent::Retap`이 되어 Engine에서
  Backspace + Key 두 걸음으로 풀리므로 합성기·어절 추적에 새 갈래가 생기지 않는다.
- 배치는 널리 쓰이는 열두 키를 따르되(하늘·땅·사람이 맨 위, ㅇㅁ은 아래 가운데) 하단
  제어 행은 우리 관례(심볼 · 이모지 · 언어 · 스페이스 · 엔터)를 지킨다.
- **잔여**: 실기기 타건 검증은 미완. 나랏글(획 추가·쌍자음)은 손대지 않았다.

추가 구현됨(v3.3): **배열은 코드다** — 조합 규칙(골격)이 컴파일타임에 고정인데 그 규칙으로
치는 자판만 사전과 함께 내려받아야 하는 것은 짝이 맞지 않았다. 세벌식·천지인이 2.4MB짜리
한국어 팩을 받은 뒤에야 목록에 나타났고, 청사진이 적어 둔 지연 로딩 순서(레이아웃 먼저,
사전 나중)도 둘이 한 파일에 있어 성립하지 않았다.
- 배열은 `taza-engine::keyboard::layouts`에 있다 — 골격마다 목록 하나(`for_skeleton`)이고,
  배열이 스스로 적는 것은 문자면뿐이다. 심볼 1·2면과 통합 검색면, 하단 행은 `shared`가
  한 벌만 갖는다.
- 격자는 코드로 적어도 격자로 읽혀야 하므로 빌더(`builder`)를 둔다: 키 하나가 낱말 하나
  (`character`·`multitap`·`layer`·`enter`), 폭·변형 문자·세로 병합은 그 뒤에 덧붙는다
  (`width`·`alternates`·`spanning`), 칸이 균등한 격자는 `uniform_row`가 한 번에 정한다.
- **사라진 것**: 팩의 레이아웃 섹션(태그 3)과 그 와이어 (역)직렬화, 형식 세대를 가르던
  marker 분기, 툴체인의 레이아웃 DSL 파서와 `--layout` 옵션, 레시피의 `layout`·`layout_name`,
  그리고 손코딩 내장 배열과 DSL 텍스트가 같은 배열을 두 번 적던 중복. 순 코드량은 줄었고
  호환성 축이 하나 없어졌다.
- **얻은 것**: 배열 선택이 사전 설치 여부와 완전히 무관해졌다. 배열이 요구하는 골격이 이
  빌드에 없는 경우가 아예 생기지 않고(`NamedLayoutSet::skeleton`이 문자열이 아니라
  `ComposerSkeleton`이다), 언어 feature를 끄면 그 언어의 배열도 링크에서 함께 빠진다.
- **치른 값**: 새 배열은 앱 판올림으로 나간다. 골격이 어차피 컴파일타임 고정이라 새 입력
  방식은 대개 판올림을 동반하므로, 순수하게 배열만 바뀌는 경우에만 치르는 값이다.
- 배열이 지켜야 할 것(폭의 합, 이어진 키가 덮은 자리, 천지인 계열의 자모 도달성, 라틴 네
  벌의 글자·변형 일치)은 컴파일러가 지켜 주지 않으므로 `tests/keyboard/layouts.rs`가 막는다.

**햅틱은 두지 않는다**: 익스텐션의 진동은 전체 접근 권한을 받아야 울리는데, 이 키보드는
기기 밖으로 아무것도 보내지 않는 대가로 그 권한을 요구하지 않는다. 켤 수 없는 스위치를
설정에 남기지 않는다.

백로그(우선순위순): 나랏글 배열(획 추가·쌍자음 — 자음을 키로 고르지 않고 만들어 가는
방식이라 또 하나의 오토마톤이다) /
검색면의 검색 입력(익스텐션 안 필드는 스스로 입력을 못 받아 전용 세션 라우팅이 필요) /
글라이드 타이핑(lexicon FST 빔서치 + InputDecoder 추상화) /
한국어 자동교정·자동 띄어쓰기(형태소 LM 전제) / iPad 분할·플로팅 /
**커서 이동 중 선택은 iOS에서 불가** — `UITextDocumentProxy`에는 선택 범위를 만드는 API가
없다(`adjustTextPosition`뿐). 순정 키보드만 쓸 수 있는 길이므로 계약에 넣지 않는다.

추가 구현됨(v2.7): **이모지·기호·얼굴 문자는 낱말에 곁들여진다** — 별도 레이어에 가둬 두지
않고, 치고 있는 어절에 달린 것을 후보 바에 함께 내놓는다. 갈래를 나눠 보이는 것이 계약이다.
- `CandidateGroup`(Word/Emoji/Symbol/Emoticon)을 후보에 실어 셸이 **그룹 단위로 인라인**
  배치한다 — 낱말 그룹만 남는 폭을 나눠 갖고 곁들이는 것은 제 폭만 차지하며, 그룹 사이는
  순정 후보 바와 같은 1pt 구분선으로 가른다. 갈래마다 글꼴 크기가 다르다(이모지는 크게,
  글자로 그린 얼굴은 작게). 갈래별 상한은 `SuggestionPolicy.annotation_limit`.
- **데이터는 팩 섹션 둘**: `annotation`(태그 5, 낱말→곁들일 것 — 키는 lexicon과 같은 조회 키
  공간, 갈래별 상한 3, 이진 탐색 색인)과 `annotation_catalog`(태그 6, 갈래별 표시 순서 —
  검색하지 않았을 때 보이는 목록은 조회 키 순서로 만들 수 없으므로 원천 순서를 따로 싣는다).
- **통합 검색면 = 레이어 3**: 하단 행에 이모지 키(심볼 · 이모지 · 언어 · 스페이스 · 엔터)를
  두어 한 번에 닿는다. 이 레이어는 키 대신 패널이 자리를 갖는다 — `KeyboardLayout.panel_rows`
  로 높이를 선언하고 프레임이 `panel_height_ratio`를 실어 주므로,
  키보드 전체 높이는 문자면과 같다. 패널 내용은 배열 데이터가 아니라 코어가 낸다
  (`Engine::annotation_panel` — 자주 쓰는 것 + 갈래별 목록, 검색어가 있으면 갈래별 결과).
  고른 것은 `select_annotation`이 진행 중 조합을 확정한 뒤 넣고 최근 사용에 남긴다
  (시크릿 필드에서는 남기지 않는다). 최근 사용은 개인화 스토어가 갖고 스냅샷에 함께 실린다.
- **원천**: 이모지·기호는 CLDR 주석 한 파일에서 오고 갈래는 코드포인트로 가른다(변이 선택자·
  ZWJ·이모지 표현 구역이면 이모지, 그 밖은 기호). 얼굴 문자는 표준 원천이 없어
  `data/sources/curated/emoticons.ko.tsv`로 갖춰 두고 `annotation-list` 형식으로 읽는다.
- 아직 없는 것: 검색면의 **검색 입력**. 익스텐션 안의 텍스트 필드는 스스로 입력을 받지
  못하므로, 문자 레이어의 키 입력을 앱이 아니라 검색어로 돌리는 라우팅(전용 세션)이 필요하다.
  지금 검색면은 자주 쓰는 것과 갈래별 목록을 훑는 자리이고, 낱말로 찾는 길은 후보 바다.

추가 구현됨(v2.8): **설정은 갈래로 나뉘고, 갈래의 기준은 사용자다** — 설정 항목이
넷에서 스물다섯으로 늘면서 화면을 나눴다. 나누는 축은 값이 코어로 가는지 셸에 남는지가
아니라 사용자가 무엇을 고치러 왔는가다(입력 보조 · 표시 · 입력감·제스처 · 개인 정보).
구현 갈래는 화면 구조에 새어 나오지 않는다.
- **코어가 판단하는 설정은 `UserPreferences`가 늘어난다**: 자동 대문자화 / 스마트
  문장부호 / 괄호 자동 짝 / 곁들이는 후보 / 길게 눌러 변형 문자 / 숫자 행 /
  후보 바 항상 표시 / 키보드 높이 / 커서 이동 감도. 언어와 무관한 부호 규칙
  (`policy::punctuation`)은 더블 스페이스 마침표와 같은 자리에서 합성기보다 먼저 본다 —
  다만 **조합 중에는 성립하지 않는다**: 어절 안의 따옴표를 갈아치우면 사전 조회 키가
  어긋난다("don't").
- **자동 대문자화는 코어가 문맥을 미리 적용해 판정한다**(`Engine::sync_auto_shift`):
  셸이 문맥을 다시 읽어 오기를 기다리면 마침표를 찍고 친 첫 글자가 소문자로 들어가므로,
  `press_at`이 방금 낸 Effect를 문맥에 얹어 다음 글자의 shift를 정한다. 사용자가 손으로
  올린 shift는 문맥이 내리지 않는다(`shift_from_auto`).
- **소리·진동·미리보기·테마·삭제 반복 속도는 셸이 갖는다**: 코어에 판단할 것이 없어
  계약을 늘리지 않는다. 백로그의 `Effect::Feedback` 안은 채택하지 않았다.
- **한 골격이 배열을 여러 벌 갖는다**: 배열이 스스로 적는 것은 문자면뿐이고 심볼면
  둘과 검색면은 공용 부품(`layouts::shared`)에서 온다 — 심볼면 세 벌이 배열마다
  복사되지 않는다. 라틴은 QWERTY·QWERTZ·AZERTY·Colemak, 한글은 두벌식·세벌식 최종과
  천지인 네 벌이고, 고른 배열은 `LanguagePreferences`가 이름으로 기억한다(판올림으로
  사라진 이름은 조용히 기본 배열로 돌아간다).
- 시프트 표기를 적지 않은 글자는 **대문자로 올라간다**(`character`). 대소문자가 없는
  스크립트에서는 같은 글자 그대로다 — 한글 자모 배열은 이 규칙에 걸리지 않는다.
- **내장 팩은 익스텐션 번들에 있다**. 설정 앱도 같은 팩을 읽어야 배열 목록·사전 상태가
  키보드와 어긋나지 않으므로 `PackStore`가 앱 안의 익스텐션 번들까지 본다.

기능 자체는 추후 구현. 지금 확보할 것은 "이 기능이 나중에 와도 계약이 안 깨진다"는 훅이다.

| 일본어 | 顔文字·기호 사전, 予測変換 학습 | 언어팩 부가 섹션(기확보) + 개인화 스토어(기확보) |
| 중국어(추후) | 필기 인식, 획순 입력, 창힐/주음 스킴 | **KeyboardFrame에 캔버스형 패널 타입 예약**. 인식 엔진은 후보 바로 합류하는 별도 InputDecoder |
| 중국어(추후) | 간체/번체 변환, 모호 병음(fuzzy), 클라우드 후보 | 클라우드 후보=지연 후보 갱신(기확보)+Full Access 게이트. 변환·fuzzy는 엔진 설정 |
| RTL(추후) | 아랍어·히브리어, 모음 부호 레이어(harakat/niqqud) | MoveCursor 논리적 이동(기확보) + KeyboardFrame 좌우 미러링 플래그 + 부호 레이어=레이어 전환(기확보) |
| 인도계(추후) | 음역↔네이티브 배열 토글 | 한 언어에 복수 Composer 등록 + 전환 이벤트 |
| 공통 | 다국어 동시 예측(언어 자동 감지) | **LM 점수의 언어 간 비교 가능성** — 아래 LM 추상화의 캘리브레이션 계약이 전제 |
| 공통 | 음성 입력 | 셸 서비스가 확정 텍스트를 기존 Commit Effect 채널로 주입 (iOS 서드파티 키보드는 시스템 받아쓰기 불가 — 자체 엔진 또는 미지원 명시) |
| 공통 | 사용자 단축어·사용자 사전 | 개인화 스토어(기확보)에 언어별+전역 네임스페이스 |

### 이번에 계약에 추가되는 것 (기능 없이 훅만)
1. **InputDecoder 추상화**: 탭 히트테스트 / 글라이드 / 필기 / 음성이 모두
   "후보 or 확정 텍스트를 만들어 Composer·후보 바에 합류"하는 병렬 단계.
2. **골격 → capability 조합**: composing(유/무), validation, conversion(상시/온디맨드),
   timer 를 Composer의 선언적 능력으로. 한국어 한자, 일본어 문자종 변환이 자연 수용.
3. KeyboardFrame에 패널 타입(키 그리드 외 캔버스 등)과 RTL 미러링 플래그 예약.
4. 케이스 변환·정규화는 로케일 인지 코어 유틸로 단일화.

## 언어모델 추상화 (v2.2 — 교체 가능 구조)

```rust
trait LanguageModel {
    fn score(&self, context: &[Token], candidate: &str) -> LogProb;  // 공통 스케일
    fn predict(&self, context: &[Token], limit: usize) -> Vec<Prediction>;
    fn metadata(&self) -> LmMetadata;  // 종류·버전·캘리브레이션 파라미터
}
```

- **랭킹 함수는 이 trait만 소비** — n-gram이든 신경망이든 랭킹·Composer·평가 하네스는 불변.
- 언어팩의 LM 섹션은 **타입 태그 레지스트리**: `ngram-v1`(현재), `neural-v1`(추후, 양자화
  가중치 mmap) 등. 로더가 태그로 디스패치, 미지 태그는 해당 섹션 무시 + 폴백.
- **구현 현황**: `ngram-v1`(bigram) 섹션 + `Pack::language_model()` 디스패치 지점 구현됨.
  Composer는 `Pack` 핸들만 받으므로(feed 시그니처) LM 교체는 팩 배포로 끝난다.
  다음 단어 예측이 LatinComposer의 단어 경계(separator·후보 선택·자동교정 직후)에 연결됨.
- **토크나이저도 팩에 포함** — LM 교체는 토큰화 교체를 수반하므로 (형태소/자모/BPE)
  LM 섹션과 토크나이저 섹션을 쌍으로 버저닝.
- **폴백 체인**: neural 로드 실패(메모리 예산 초과 포함) → ngram → lexicon-only.
  48MB 하한 기기에서 neural은 선택 로드.
- **캘리브레이션 계약**: score는 언어 간 비교 가능한 로그확률 스케일로 정규화
  (다국어 동시 예측의 전제). 캘리브레이션 파라미터는 팩 메타데이터에.
- 평가 하네스가 교체 게이트: 같은 평가 셋에서 LM A/B 비교 → 회귀 없을 때만 팩 배포.

### 파이프라인 적정성 재점검 (우선 3언어)
- 영어: lexicon+ngram 파이프라인이 글라이드(FST 빔서치가 같은 lexicon 사용)까지 커버 — 적정.
- 한국어: 형태소 단위 LM이 자동 띄어쓰기 제안·자모 오타 보정·한자 변환(형태소→한자 후보)의
  공통 기반 — 적정. 단 형태소 분석기 품질이 파이프라인 상류 리스크로 추가됨.
- 일본어: AzooKey 사전+엔진에 랭킹 개인화만 코어 측 — 엔진 내부 랭킹과 코어 LM 점수의
  이중 구조가 생기므로, 엔진 출력 후보에 코어 개인화 부스트를 더하는 "후처리 재랭킹"으로
  경계를 고정 (엔진 내부에는 개입하지 않음).

## 커서 이동 (v2.1)
- `InputEvent::CursorMoved { context: EditorContext }`를 코어 이벤트로 추가.
  기본 정책: 진행 중 composing은 finalize (언어별 finalize 정책 적용).
- iOS는 커서 이동 통지가 불완전(selection 변경 콜백 비신뢰) — 통지를 신뢰하지 않고
  **문맥 스냅샷 불일치 감지(reconciliation)를 커서 이동 추정의 주 신호**로 삼는다.
- 코어가 커서를 움직이는 Effect `MoveCursor(offset)` 추가 (iOS adjustTextPosition /
  Android setSelection). 스페이스바 길게 눌러 커서 이동(양 플랫폼 관습)은
  포인터 스트림 → 코어 판정 → MoveCursor 경로로 처리.
- offset 단위는 코드포인트로 하되 그래핌 경계 스냅은 코어가 산출.
  RTL(아랍어·히브리어, 추후)의 논리적/시각적 방향 구분은 Effect 의미를
  "논리적 이동"으로 고정해 미리 봉합.
- 확정 텍스트 내부로 커서 이동 시 재변환(일본어 관습)은 CommittedText 이력이
  남아 있는 범위에서만 지원 — v1 범위 제외, 계약만 예약.
- **합성 재개(adoption, 구현됨)**: 커서 이동 후에도 그 위치에서 합성·자모 분해 삭제가
  이어져야 한다. composing이 없을 때 Composer가 EditorContext의 커서 앞 글자를 분해해
  composing으로 되가져오고(delete_before_commit로 원문 치환), 이후 입력·Backspace는
  일반 합성 규칙을 따른다. 통로(feed의 context 파라미터)는 언어 공통, 무엇을 어떻게
  분해할지는 언어별 정책 — 한국어는 음절→자모(복합 모음·겹받침 포함) 분해로 도깨비불
  재개와 자모 단위 삭제를 재현하고, 분해 불가 문자는 delete_before_commit=1 passthrough.
  텔렉스 성조 소급 수정, 인도계 클러스터 재진입도 같은 통로를 쓴다.

## 특수문자·기호 (v2.1)
- 심볼 레이어는 KeyboardFrame의 레이어 전환으로 표현 (숫자/기호 1·2면, 통합 검색면 = 레이어 3).
  레이어 구성·기호 배치는 배열이 갖는다 — 언어별 관습(일본어 「」·。、, 스페인어 ¿¡,
  프랑스어 «» 등)은 그 언어의 배열이 자기 심볼면을 적어 수용한다.
- composing 중 특수문자 입력의 언어별 의미를 `Separator` 처리 정책으로 명시:
  한국어=음절 확정 후 기호 삽입, 일본어=현재 후보 확정 후 기호(。、는 변환 트리거 겸용),
  영어=단어 경계로 자동교정 발동.
- 프랑스어 구두점 앞 공백, 스마트 구두점(더블 스페이스→마침표), 자동 페어링은
  자동교정 엔진의 규칙 레이어 소관 — composition과 분리.
- 이모지·기호·얼굴 문자(구현됨): 후보 바에 갈래별로 곁들이고 통합 검색면에서 훑는다.
  목록·검색·최근 사용은 코어 소관(annotation·annotation_catalog 섹션 + 개인화 스토어),
  삭제는 ZWJ 시퀀스 통째 삭제 정책 테이블 적용(예약).
